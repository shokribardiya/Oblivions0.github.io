Platform

Infrastructure philosophy

The platform is designed so that every privileged surface — files, models, users, and administration — sits behind the same set of architectural guarantees.

Zero trust

No request is trusted by network location alone. Every call to a privileged interface is authenticated and authorized independently, on every request.

Defense in depth

Security is layered — network, gateway, application, and data — so that no single control failure exposes the system.

Least privilege

Sessions and services are granted the minimum access required for their function, scoped by role and by object.

Secure by default, fail closed

Unclear or failed authorization decisions deny access rather than falling back to an open state.

Security & Trust

What "secure" means here, stated plainly.

This page states the principles Oblivion designs against. It is not a claim that any system is unhackable, and nothing here is "military-grade" — that phrase gets used without evidence often enough that we'd rather just describe the actual practices.

Secure development

Code review, dependency review, and threat modeling are part of how a system ships, not a step added afterward. This file's own rendering layer is an example: everything dynamic is escaped through OblivionSecurity.esc(), and no dynamic script injection, eval(), or unsanitized HTML construction is used anywhere in it.

Auditability

Privileged actions are logged with enough context to reconstruct what happened and why — not just that something happened. The Control Center's audit log demonstrates the shape of this; production logging ships to a backend audit service rather than living in the browser.

Data handling

Data is classified, access is scoped to what a given session actually needs, and storage and transport are encrypted. What a system collects is bounded by what it needs to do its job.

Incident response

Systems are built assuming something will eventually go wrong: clear ownership, a defined escalation path, and postmortems that change the system rather than just closing a ticket.

Responsible disclosure

If you find a genuine security issue in something Oblivion operates, report it through the security disclosures link in the footer rather than public channels, and allow time to investigate and fix it before any public discussion.

For the infrastructure layers this maps onto in production, see Platform.
